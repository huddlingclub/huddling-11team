# 산출물 진척 점수 정책

> 코드 40% · 디자인 30% · 문서 15% · 기획 15%
>
> 공통 기준 70%와 팀별 목표 30%를 합산합니다. 행사 중 새로 갖춰진 산출물만 점수에 반영합니다.

- 문서 상태: 대화에서 합의한 수치 정책 정리. 실제 집계 전에는 아래 설정표를 채워야 합니다.
- 적용 단위: 팀별 저장소. 팀 인원으로 점수를 나누거나 보정하지 않습니다.
- 점수의 의미: 필요한 산출물이 얼마나 갖춰졌는지 나타내는 진척 지표입니다. 작품의 품질·기능의 정상 동작·최종 심사 성적을 뜻하지 않습니다.
- 시연 방식: 실제 저장소 자료를 바탕으로 재생합니다. 레이싱 순위는 최종 해커톤 심사와 별개입니다.
- 문서 범위: 측정 기준과 점수 계산. 트랙·캐릭터·의상·레벨·아이템·이동 거리 등 게임 형태는 다루지 않습니다.

## 1. 한눈에 보는 가중치

| 분야 | 공통 기준 | 팀별 목표 | 전체 비중 |
|---|---:|---:|---:|
| 코드 | 28% | 12% | **40%** |
| 디자인 | 21% | 9% | **30%** |
| 문서 | 10.5% | 4.5% | **15%** |
| 기획 | 10.5% | 4.5% | **15%** |
| **합계** | **70%** | **30%** | **100%** |

공통 기준은 팀 사이의 비교를 위한 조건이고, 팀별 목표는 각 서비스의 특성을 반영하는 조건입니다. 같은 평가 묶음 안에서는 항목별 점수를 똑같이 줍니다.

## 2. 무엇을 측정하나

| 분야 | 측정할 것 | 점수만으로 판단하지 않는 것 |
|---|---|---|
| 코드 | 사전에 정한 필수 구현 파일의 제출 여부 | 기능 동작, 테스트 통과, 코드 품질 |
| 디자인 | 사전에 정한 필수 화면·상태 산출물의 제출 여부 | 심미성, 사용성, 디자인 품질 |
| 문서 | 사전에 정한 필수 문서 항목의 기록 여부 | 글의 설득력, 문서 분량 |
| 기획 | 사전에 정한 필수 기획 항목의 기록 여부 | 아이디어의 우수성, 사업성 |

- 공통 폴더 구조와 확장자로 분야를 분류합니다. 실제 경로는 설정표에 고정합니다.
- 각 저장소의 목표를 보고 팀별 조건을 작성합니다. 실행 중 AI가 내용을 해석해 점수를 매기지 않습니다.
- 조건은 확인할 파일·항목과 판정 방법을 미리 정해 둡니다. 파일이 있다는 이유로 관련 목표를 전부 달성했다고 추정하지 않습니다.
- 외부 산출물은 링크와 요약·캡처를 저장소에 제출하면 인정 대상이 됩니다. 링크 등록과 외부 도구의 실제 작업량은 구분합니다.
- 같은 성과를 커밋·push·PR·merge·review·issue 횟수로 반복 가산하지 않습니다. 코드 줄 수·파일 용량·작성 분량도 독립 점수가 아닙니다.

### 제출과 득점은 구분

제출한 작업은 `진행 중`으로 봅니다. 병합되거나 산출물이 확인된 뒤에도, 등록된 조건을 충족한 항목만 득점합니다. PR을 올리거나 병합한 사실 자체에는 보너스를 주지 않습니다.

`산출물 확인`은 등록된 파일·항목이 제출 조건을 충족했는지 확인하는 절차입니다. 실제 동작이나 주관적인 품질을 평가하는 절차가 아닙니다. 외부 링크 내부 내용의 자동 확인은 **수집 가능 여부 확인 필요**입니다.

## 3. 기존 성과와 신규 성과

**전체 기준은 고정하고, 행사 중 새로 달성한 조건만 가산합니다.**

예를 들어 전체 기준이 100점이고, 행사 전에 60점을 이미 달성한 팀이 행사 중 20점을 더 달성했다면 신규 점수는 **20점**입니다. 남아 있던 40점의 절반을 끝냈다고 50점으로 다시 환산하지 않습니다.

- 기준 시점에 이미 충족한 조건은 기존 성과로 따로 표시합니다. 점수 계산의 분모에서는 빼지 않습니다.
- 기준 시점에는 미충족이었고, 집계 시점에 제출·확인 조건을 충족한 항목만 신규 성과입니다.
- 기준 시점의 상태를 확인할 수 없으면 신규 여부를 확인하기 전까지 해당 항목은 0점으로 계산합니다. 확인 후 재계산합니다.
- 기존 성과를 삭제했다가 복구해도 신규 성과로 바뀌지 않습니다.

준비된 성과가 있는 팀은 신규 점수의 최대치가 100점보다 작을 수 있습니다. 이것은 남은 목표를 재환산하지 않기로 한 선택의 결과입니다.

## 4. 계산 방법

### 평가 묶음 점수

각 분야에는 `공통 기준`과 `팀별 목표` 두 묶음이 있습니다.

```text
평가 묶음 점수 = 현재 유효한 신규 달성 항목 수 / 사전에 정한 전체 항목 수 × 100
분야 점수 = 공통 기준 점수 × 0.70 + 팀별 목표 점수 × 0.30

종합 점수 = 코드 점수 × 0.40
          + 디자인 점수 × 0.30
          + 문서 점수 × 0.15
          + 기획 점수 × 0.15
```

`현재 유효한 신규 달성`은 기준 시점에는 미충족이었고, 현재는 확인 조건을 충족한 상태입니다. 반복 제출·삭제·복구 횟수가 아니라 현재 상태를 한 번만 셉니다.

각 묶음과 분야, 종합 점수는 모두 0~100점입니다. 같은 묶음 안에서는 항목별 동일 배점을 적용합니다. 공통과 팀별 묶음의 항목 수가 달라도 두 묶음을 섞어 단순 평균하지 않습니다.

### 계산 예시

아래는 기존 성과를 분자에서 제외하고 전체 항목 수를 분모로 유지해 각 묶음의 점수를 계산한 예시입니다. 실제 팀 점수가 아닙니다.

| 분야 | 공통 기준 점수 | 팀별 목표 점수 | 분야 점수 | 종합 점수에 반영 |
|---|---:|---:|---:|---:|
| 코드 | 80 | 50 | 71 | 28.4 |
| 디자인 | 60 | 100 | 72 | 21.6 |
| 문서 | 100 | 0 | 70 | 10.5 |
| 기획 | 50 | 50 | 50 | 7.5 |
| **합계** | | | | **68.0점** |

## 5. 반복 제출·삭제·확인 실패

| 상황 | 처리 |
|---|---|
| 같은 조건을 여러 번 제출 | 한 번만 득점 |
| 점수를 받은 파일이 삭제돼 조건을 충족하지 못함 | 해당 점수 회수 |
| 삭제한 파일을 복구해 조건을 다시 충족 | 원래 점수만 회복. 추가 점수 없음 |
| 자료를 정상 조회했지만 조건 미충족 | 해당 항목 0점 |
| 자료 수집 실패·접근 불가 등으로 확인하지 못함 | 확인하지 못한 항목을 우선 0점 처리하고 `확인 실패`를 별도 기록. 총점·순위 계산에는 포함 |
| 실패했던 자료를 나중에 확인 | 기준 시점과 현재 상태를 확인해 재계산. 같은 성과 중복 가산 없음 |

확인 실패로 인한 0점과 실제 미제출 0점은 숫자는 같아도 원인이 다릅니다. 원인·확인 시점을 함께 남깁니다. 일부 항목을 못 읽었다고 정상 확인된 다른 항목의 점수까지 지우지 않습니다.

평가 조건 자체가 미등록인 경우에는 산출물 미제출과 구분해 `설정 필요`로 기록합니다. 0으로 나누거나 해당 분야의 비중을 다른 분야에 자동으로 넘기지 않습니다. 설정이 끝나기 전에는 점수가 준비되지 않은 상태로 취급합니다.

## 6. 실제 집계 전에 채울 설정표

정책 선택은 위에 정리했습니다. 아래는 실제 자료를 보고 채울 적용 설정입니다. 이 표가 비어 있는 상태에서는 확정된 채점표가 아닙니다.

| 설정 | 채워야 할 내용 | 현재 상태 |
|---|---|---|
| 참가 저장소 | 조회되는 저장소 중 실제 팀과 연결할 목록 | 확인 필요. 앞선 조사에서 16개 저장소가 조회됐으나 0team·0team-3은 참가 대상 확인이 필요했고 4team은 접근되지 않았음 |
| 집계 구간 | 기준 시점·종료 시점과 팀별 근거 커밋 | 적용 전 기록 |
| 공통 분류 경로 | 네 분야의 공통 폴더·확장자와 중복 없는 분류 규칙 | 확정한 실제 경로 입력. 기존 저장소의 파일 이동은 별도 작업 |
| 공통 기준 | 분야별 필수 항목 목록·개수·확인 방법 | 작성 필요 |
| 팀별 목표 | 저장소 목표에서 정한 분야별 항목 목록·개수·확인 방법 | 작성 필요 |
| 제출·확인 근거 | 인정할 브랜치·PR 상태, 병합 또는 확인 사실을 남길 방식 | `진행 중`과 득점을 구분할 수 있게 등록 |
| 외부 자료 | 링크·요약·캡처의 저장 위치와 제출 조건 | 외부 자료를 쓰는 항목에 등록 |
| 기존 성과 | 기준 시점에 이미 충족된 항목과 근거 | 팀별 기록 |

코드·디자인·문서·기획의 공통 조건은 같은 평가 묶음 안에서 전 팀에 동일하게 적용합니다. 항목 수와 기준은 집계 전에 고정하고, 점수를 올리려고 경기 중 분모를 줄이지 않습니다. 위 항목을 작성할 때 파일 존재·지정 항목 기록처럼 확인 가능한 조건만 사용합니다.

## 7. 서비스에 적용하는 순서

1. **설정:** 참가 저장소·집계 구간·공통 경로·공통 조건·팀별 조건을 기록합니다.
2. **기준선 기록:** 집계 시작 시점의 기존 달성 상태를 보관합니다.
3. **확인:** 실제 저장소 자료에서 제출 상태와 등록 조건의 충족 여부를 확인합니다.
4. **계산:** 신규 성과만 세고 공통 70%·팀별 30%, 분야별 40·30·15·15를 적용합니다.
5. **검토:** 반복 제출·삭제·복구·수집 실패를 대조한 뒤 시연용 기록을 만듭니다.

다음 사례를 실제 계산에 대조합니다.

| 확인 사례 | 기대 결과 |
|---|---|
| 모든 항목이 신규 달성 | 종합 100점 |
| 코드만 전부 신규 달성 | 종합 40점 |
| 모든 분야의 공통 기준만 신규 달성 | 종합 70점 |
| 모든 분야의 팀별 목표만 신규 달성 | 종합 30점 |
| 행사 전 이미 충족한 항목을 다시 제출 | 신규 점수 0점 |
| 신규 달성 항목을 삭제 후 복구 | 점수 회수 후 원래 점수만 회복 |
| 수집 실패 항목을 뒤늦게 확인 | 우선 0점에서 실제 확인 결과로 정정 |

## 8. 현재 구현과의 관계

이 문서는 **합의한 정책**입니다. 문서 등록만으로 현재 서비스의 점수 계산이 바뀌지는 않습니다.

확인 기준은 원격 `82ce695875d7fecda998904c2b6c745f78256b26`입니다.

- 현재 [점수 계산 코드](../src/lib/core.ts)는 커밋 무게·머지 보너스·충돌 감점·부스트 등을 사용합니다. 이 문서의 항목 충족률 기반 계산과 다릅니다.
- 현재 [데이터 수집 구조](./infra.md)는 커밋·PR 정리본과 현재값을 제공합니다. 커밋·PR 개수만으로 이 정책의 산출물 달성률을 계산할 수는 없습니다.
- 적용하려면 위 설정표와 기준 시점의 파일·항목 상태를 연결하는 작업이 필요합니다. 실제 수집·판정 가능 여부가 확인되지 않은 항목은 **수집 가능 여부 확인 필요**로 남깁니다.
- [기존 기획](./plan.md)에 적힌 게임 연출과 화면 구성은 별도입니다. 점수 정책을 적용할 때는 이 문서의 수치·측정 합의와 기존 구현의 차이를 확인합니다.

이 문서는 새로운 게임 형태나 추가 기능의 구현 요청을 포함하지 않습니다.
